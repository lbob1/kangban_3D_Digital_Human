## 逐条对照

### 1. 上下文死亡螺旋（长会话越改越乱）
**实例**：Day1~Day5 直接对话式开发，后期出现 AI 重复做已完成的改动、基于过时假设写代码。**对策**：Day6 起规划双件套（主文档+执行提示词）——每次会话用执行提示词完整重建上下文，锚点（git/测试/head/端口）开工先核对；Day10 把该流程固化为 Skill `new-day-plan`。

### 2. 过度信任 AI 汇报
**实例**：AI 曾汇报「测试全绿」但汇总例数与实测不符（Day9 开工实测 603 例 vs 主文档口径 586 例）。**对策**：验收报告只认 `--collect-only` 实测数；每步汇报必须带 commit hash 与实测输出；验收表禁止无证据的 ✅。

### 3. 补丁叠补丁
**实例**：Day7 标签后联调实测暴露 7 个问题，若零散热修会腐化架构。**对策**：当天 4 笔提交全部收敛进 ADR-025（点播双通道汇合），每笔 commit 信息写明问题与修法；教训——**联调补丁也要进决策记录**，不能「改完就算」。

### 4. 范围蔓延
**实例（预防证据）**：大纲字面要求 redis/vite/nginx/Langfuse，实际全不做（Day6 不做清单、Day10 D1/D2 差异表如实标注）；演示脚本不扩「顺手优化」。**对策**：每份主文档 §1.3 不做清单与任务清单同等地位；不做的事情写明理由与出处，防止次日重提。

### 5. 幻觉测试（指标好看但测错了东西）
**实例（口径风险）**：33 场景基线里 S1 是确定性关键词桩——若直接宣称「S1 准确率 100%」就是自欺。**对策**：口径声明节强制区分「桩口径测接线」与「真实 laya 50 条测推理」（96.4%）；声纹合成口径扫描不替代真人复调（列后续可选）；估算 token 节省显式标「估算口径」。

### 6. 监控盲点
**实例**：Day1~Day9 只有日志，无 metrics 端点，延迟问题全靠一次性跑批（POC-08）。**对策**：Day10 补齐 `/metrics`（进程计数+decision_logs 聚合，与 gate.py 同口径）+ `trace_lookup` 全链 HTML 报告——但保持零外部依赖（否决 Langfuse 的理由本身写入决策表）。

### 7. 成本失控
**实例（预防证据）**：S1 闭环率 68.75%/62%（多数流量不碰大模型）、ToolCallGuard 单轮 ≤8 且实测全部 ≤1、记忆 top-5 注入、prompt cache 未实现就如实 N/A。**对策**：成本数字进 README 且可复算；预算闸进 Guard 而非靠自觉。

### 8. 规则投毒（约束被静默放宽）
**实例（预防证据）**：AGENTS.md 十天只有增补（Day10 复盘踩坑条目），既有禁区一字未动；D2 变更走「用户裁决→文档修订→只改相关内容」流程。**对策**：只增不改+`git diff --numstat` 实证+人审；AI 无权放宽任何红线，冲突只能停下提问。

### 9. 依赖失控（随手装包/下载模型）
**实例（预防证据）**：全程主依赖零新增（Day10 纯本地 trace 方案明确「不装 langfuse SDK」）；模型权重白名单仅 laya 一条（pinned revision，POC-03 验证）；外部服务全经 POC 门禁与 Provider 适配器。**对策**：主文档 §6「新增依赖默认无」；任何新依赖需决策点裁决。

### 10. 无回滚上线
**实例**：Day10 演练三条回滚通道（git 代码回滚 500→200 / 镜像回滚 / alembic 双向可逆 0018→0017→0018），且演练中真实遭遇 Docker 存储损坏——按 SOP 恢复、数据零丢失（对账 6/38/63/79）。**对策**：回滚路径写进门禁六项清单；演练前先做数据丢失风险评估（73 行睡眠数据案例→测试库口径裁决）；备份纪律（动卷前 pg_dump）。

## 数字收官（全部实测可复算）

- 测试：720 例全绿（702 基线 + 8 metrics + 10 trace_lookup）；工具行覆盖 100%；
- 评测：33/33 场景，敏感召回/幻觉拦截/任务成功率 100%，S1 闭环率 68.75%，gate exit 0；
- 真实口径：Day6 laya 意图准确率 96.4%；Day5 POC-08 首 token -84%、e2e P95 -57%；
- 交付：Docker 三服务一键启动、tag `final`、16 项验收（见 Day10_验收报告.md）。
