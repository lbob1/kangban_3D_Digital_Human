# 工作流选型说明

> 范围：Day1 只写选型结论与边界，不创建任何业务图或 Agent 实现。

## 1. 三种流程形态与适用边界

| 形态 | 适用场景 | 技术载体 | 示例 |
| --- | --- | --- | --- |
| 直线流程（确定性代码） | 固定、单步、可枚举操作 | FastAPI 路由 + 领域服务 | 播放/暂停/音量、健康检查、媒体检索、家属签到计数与发奖事务 |
| Agent Loop（受约束主控） | 复杂、开放域、多工具组合请求 | 受约束 CompanionAgent（ReAct） | 多步骤信息搜集（天气+日程+提醒） |
| LangGraph 子图 | 有循环、分支、副作用、断点恢复、HITL 的长流程 | LangGraph + PostgreSQL Checkpointer + Interrupt | 用药确认重试升级、健康分级与人工确认 |

### 直线流程

简单确定性请求 在规则层 / System One 闭环（目标闭环率 ≥ 60%，EM-05），不进入大模型：
「换一段、停、大声点」直接命中规则；家属签到按确定性领域服务实现（服务端日期、唯一约束、幂等发奖）。

### Agent Loop

仅一个受约束 CompanionAgent（ADR-003）：
- Tool 单次对话 ≤ 8 次；同一 Tool 一分钟重复 3 次熔断（NFR-10）。
- Tool 参数 schema 不含可信 `elder_id`，身份只从 Runtime Context 注入。
- 用药与健康长流程只调用对应 LangGraph 子图，不写平行逻辑。

### LangGraph 子图

- 用药子图（Day7 实装，ADR-023）：`calling → waiting_confirm → confirmed | retry → escalated`，重试循环边 ≤3 次（1 次首呼 + 至多 3 次重试）、设备离线走调度器退避 recall 再入图，失败建漏服工单；每次迁移写 Checkpoint。
- 健康子图（Day8 实装，ADR-026）：绿（入库）/ 黄（护工 interrupt HITL）/ 红（医生 interrupt + 医院 mock + 紧急工单）；确认前无任何副作用（引擎级保证，非应用层约定）。
- Checkpointer 使用 **AsyncSqliteSaver（SQLite 文件，med/health 各一）**——ADR-023 对 ADR-004（PostgreSQL checkpointer）的替代决策：图断点与业务库隔离、文件级恢复简单；与主数据平台「同库」的原设想已按实测口径修正。

## 2. 不建 Agent 的能力

| 能力 | 定位 | 理由 |
| --- | --- | --- |
| 方言语音 | 语音/文本适配步骤 | 只经官方 ASR/TTS API 与可选语义规范化接入现有链路（ADR-015），不改变路由与 HITL |
| 家属签到与礼包 | 确定性领域服务 | 数据库事务 + 唯一约束 + 幂等键已足够（ADR-016），不用 Prompt/Agent |
| 媒体播放控制 | 规则层直线流程 | 可枚举指令，无需推理 |

## 3. 安全贯穿原则

- 敏感意图一票否决，优先于普通路由；命中进入人工确认队列，不进入开放域 Agent。
- 高危副作用（通知、HIS、紧急工单）必须 HITL，确认前无副作用。
- `elder_id` 只来自服务端 Runtime Context，不信任客户端或模型传参。

## 4. Day1 边界

Day1 仅交付：FastAPI 骨架、`/health`、Settings、trace_id 日志、11 表 ORM 与迁移。
规则层、System One、CompanionAgent、LangGraph 子图、MCP 工具、调度外呼均为后续阶段内容，本文档只冻结选型边界。
