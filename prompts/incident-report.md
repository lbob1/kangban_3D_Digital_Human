# incident-report · 基础设施事故复盘提示词骨架

> 来源沉淀：Day10 宿主机磁盘满 → Docker Desktop containerd 存储损坏事故（docs/Day10_回滚演练.md §4）。

```
针对今日发生的基础设施事故（现象：<一句话>），生成复盘留档：

1. 时间线与现象：按发生顺序列每一步的观察证据（命令+输出原文），区分「事实」与「推断」；
2. 根因：写到可操作的层面（如「磁盘满导致 VHDX 只读」而非「环境问题」）；
3. 恢复 SOP：逐步可重放的恢复命令序列，标注每步的风险与前置条件；
4. 数据完整性对账：恢复后与事故前基线逐表对账（基线必须在事故前已记录）；
5. 经验教训：至少一条反直觉认知（如「磁盘满不是变慢，是静默损坏」）；
6. 是否沉淀为 AGENTS.md 踩坑条目【只增不改，人审】与 prompts/incident-report 模板迭代。

禁止：在根因未证实前写「原因可能是」当结论；把恢复过程写成教程式乐观叙事而略过中间失败尝试。
```
